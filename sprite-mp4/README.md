# FrameFlow — 이미지 → MP4 변환기

이미지 여러 장을 파일명 자연 정렬 순서로 이어 붙이고, 프레임별 밀리초(ms) 재생 시간을 설정해 MP4로 저장하는 정적 웹앱입니다. (빌드 과정 없음)

## GitHub Pages 배포
1. GitHub에서 새 공개 저장소를 만들고 **이 폴더의 모든 내용**(`index.html`, `style.css`, `app.js`, `vendor/`, `.nojekyll`)을 저장소 루트에 업로드합니다. (`vendor/` 폴더 누락 시 앱이 동작하지 않습니다.)
2. Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)` → Save.
3. 배포된 `https://<사용자명>.github.io/<저장소명>/` 주소로 접속합니다. (모든 경로가 상대 경로라 하위 경로 배포에서도 동작)

## 사용법
1. 이미지를 선택·드래그·붙여넣기(Ctrl+V)로 추가합니다. 파일명 자연 정렬(1 → 2 → 10)이 자동 적용됩니다.
2. 기본 시간(60/100ms) 또는 각 프레임별 ms를 지정합니다. 순서는 드래그 또는 ↑↓ 버튼으로 바꿉니다.
3. 영상 크기·배경색을 정하고 **MP4 다운로드**를 누릅니다.

## 로컬 테스트
ES 모듈을 사용하므로 `index.html`을 더블클릭(file://)하면 동작하지 않습니다. 폴더에서 `python3 -m http.server` 후 `http://localhost:8000` 으로 접속하세요. (WebCodecs는 https 또는 localhost에서만 동작)

## 주의
- Chrome/Edge 최신 버전 권장(WebCodecs `VideoEncoder` + H.264 인코딩 필요). Firefox/Safari는 H.264 인코더 지원 여부가 환경마다 달라 변환이 안 될 수 있으며, 이 경우 안내 메시지가 표시됩니다.
- `vendor/mp4-muxer.esm.js`는 mp4-muxer 5.2.2(MIT)에 **마지막 프레임 duration 패치**(`[FrameFlow patch]`)를 적용한 사본입니다. 원본 라이브러리는 마지막 프레임의 재생 시간을 직전 프레임 값으로 기록하는 문제가 있습니다. 라이브러리를 교체/업데이트하면 이 패치를 다시 적용해야 합니다. CDN을 쓰지 않으므로 오프라인에서도 동작합니다.
- 투명 PNG는 설정한 단색 배경 위에 합성됩니다(H.264 MP4 알파 미지원).
- 영상 해상도는 최대 3840×2160이며 홀수 픽셀 크기는 짝수로 내림 처리됩니다.
- 모든 프레임은 디코딩된 상태로 메모리에 유지됩니다. 4K 이미지 수백 장처럼 매우 큰 입력은 브라우저 메모리를 많이 사용합니다.
- 모든 이미지 처리와 인코딩은 사용자의 브라우저에서 실행되며 서버로 업로드되지 않습니다.
